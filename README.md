# redmine-excel-sync

自動將 Redmine 單的最新狀態同步到進度 Excel，產出制式差異文件，並可透過 Claude Code 對最新進度提問。

> 內部流程優化工具，僅在公司自有環境使用。

---

## 解決什麼問題

SA 每次更新進度 Excel，都要逐筆對照 Redmine 單的狀態，耗時又容易漏。
本工具把這段工作自動化：

1. 從 Redmine 抓取最新單狀態
2. 與上一版進度 Excel 比對
3. 更新 Excel 並另存新版
4. 產出制式差異文件（本次異動了什麼）
5. （可選）由 Claude Code 檢查異常、回答進度問題

---

## 架構

```
【固定流程】不使用 AI，每次結果一致
Redmine → 擷取 → 比對 → 更新 Excel（含「原始資料」工作表）→ 產差異文件

【AI 輔助】需安裝 Claude Code，未安裝時自動略過
・流程中：結構檢查、異動合理性檢查等，只產報告、不直接改檔
・流程後：讀取最新 Excel，回答「目前還剩哪些項目？」等問題
```

原則：**程式負責偵測、Claude 負責解讀與建議、人負責決定。**

## 使用方式


### 問答範例

- 目前還剩哪些項目？
- 哪些單已經逾期？
- 王小明手上還有幾張未結案？
- 這次有哪些單狀態退回？

> 每題由 Claude Code 依 `CLAUDE.md` 的規則，以程式讀取最新 Excel 的「原始資料」工作表回答。

---

## 設定說明


### `CLAUDE.md`

定義 AI 讀取資料的方式與判斷規則，也是固定流程與 AI 之間**唯一的正式約定**：

- 資料位置：取 `output/` 中檔名日期最新的進度檔，只讀「原始資料」工作表
- 讀取方式：一律以 pandas 篩選統計，不目測計數
- 欄位說明：單號、主旨、狀態、負責人、完成率、預計完成日
- 判斷規則：「剩下」= 狀態不是已結案；「逾期」= 預計完成日早於今天且未結案
- 判斷不出來時：先說明採用的假設再回答

> 修改「原始資料」工作表欄位時，**必須同步更新 `CLAUDE.md`**。

## 實作步驟

![實作步驟](./implementation-steps.png)

| 步驟 | 內容 | 子項目（除標示必要外皆可選） |
|---|---|---|
| 0. 執行入口與環境 | 建立 `progress.bat` | 0.1 可攜式 Python（必要）、0.2 環境檢查 |
| 1. 欄位約定與 AI 規則 | 約定檔名、工作表、欄位，寫成 `CLAUDE.md` | — |
| 2. Redmine 擷取 | 呼叫 API 抓單、處理分頁 | 2.1 狀態對照表、2.2 對照缺漏建議（AI）、2.3 資料品質（AI） |
| 3. 讀取舊版 Excel | 依單號整理上一版資料 | 3.1 結構檢查（AI） |
| 4. 差異比對 | 新增、狀態變更、移除 | 4.1 異動合理性檢查（AI） |
| 5. 更新 Excel | 寫入新狀態、保留格式、產生原始資料工作表 | 5.1 樣式與下拉選單 |
| 6. 差異文件 | 依範本輸出本次異動 | 6.1 文件摘要（AI）、6.2 Teams 通知 |
| 7. 完成執行入口 | 失敗中止、連續問答、暫停確認點 | 7.1 執行紀錄、7.2 錯誤診斷（AI）、7.3 Streamlit 介面、7.4 常用問題快捷、7.5 回答存檔、7.6 排程更新、7.7 Skill 化 |
| 8. 驗收 | 乾淨電腦實測，Excel 與 AI 回答皆正確 | 8.1 規則自我修正（AI） |

## 注意事項

- **執行前請關閉進度 Excel**，否則檔案被鎖住無法寫入
- 程式只修改儲存格的值，原有的文字顏色、背景、下拉選單會保留；新增列會複製上一列樣式
- Redmine 狀態若不在 `status_mapping` 中，**不會寫入**，會記錄在 log 等待人工處理
- AI 檢查只產出報告，**不會直接修改 Excel 或設定檔**
- 排程只執行固定流程，不含 AI 步驟與問答
